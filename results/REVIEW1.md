# Independent review1 — uncommitted sleepC and kagglePrep

Reviewed on 2026-11-07 against HEAD, including the tracked diff, nonignored untracked files, saved results, and the source embedded in `step4/upload/run.py`. No implementation edits or commits. Priorities: P1 = correctness/safety defect; P2 = material reliability or preparation defect.

## Findings, ranked by severity

1. **P1 — Fact revisions discard the incoming authority, allowing a weaker notice to overwrite a stronger revision.** `hippocampus/core.py:124`, `hippocampus/core.py:127`, `hippocampus/core.py:138`.

   The new `add()` branch checks the incoming trust but calls `update()`, whose event carries only text/entities/time. Trust, source and metadata remain those of the original assertion. Reproduced entirely in memory: add a trusted-source original with trust **0.2**, add a revision with trust **1.0**, then add another notice with trust **0.3**. All three share the same ID; the final text is the 0.3 assertion, because the 1.0 revision still has stored trust 0.2. This violates the documented protection against lower-trust overwrites and also loses revision provenance. Existing tests check only a lower-trust update against an initially high-trust original.

   **Fix:** persist the incoming revision's authority/provenance in the versioned event and compare subsequent notices against the current version's authority. Add the increasing-then-decreasing trust sequence, including rebuild/restore, to the tests.

2. **P1 — The new pre-gate still accepts destructive candidates when routing hides them and their norm is below the cap.** `baselines/sleep.py:193`, `baselines/sleep.py:202`, `baselines/sleep.py:208`, `baselines/tests/test_sleep.py:175`.

   Canary drift is checked only on routed outputs; the none centroid is itself constructed from those canary prompts. A candidate receiving no gate/canary routes contributes no evidence about its behavior, yet identical outputs permit acceptance. The norm check rejects the particular injected damage at roughly 289 times the base norm; a ratio below 1 is not a behavioral safety guarantee.

   Reproduced using the actual three-cycle smoke world, real router/hippocampus/gate, and FakeBackend: make cycle 3 broken and override its norm stand-in to **0.99**. The candidate is accepted with `changed_canaries=[]`, identical current/candidate gate scores, and then routes **all six fact queries** to `Final answer: broken`. The 0.99 value is a test-double input, not a measured HF ratio; this demonstrates the missing coverage check. The current hidden-damage test always gives the broken fake a ratio of 10, so it cannot detect this case.

   **Fix:** require evidence that exercises each proposed expert and the routes it can displace. At minimum, test candidate behavior on trusted training/replay validation and include independent gate coverage for retained facts/other affected families; defer candidates with no relevant gate coverage. Add the below-cap, router-hidden damage case. Do not describe the norm cap alone as resolving the routing blind spot.

3. **P2 — The fact identity index does not follow release or trust changes.** `hippocampus/core.py:463`, `hippocampus/core.py:570`, `hippocampus/core.py:585`.

   `_fact_ids` is maintained only during add/update. Reproduced: add a trusted-source original with `quarantine=True`, release it, then add a trusted update notice. Release never registers its identity, so the notice creates another ID and default/deep recall returns **both Mira and Sora**. Rebuild repeats the same omission. Changes in trust can likewise leave the pointer selecting the wrong assertion; tombstoning the indexed member does not select another eligible member when duplicates exist. The new lifecycle test covers only a single indexed identity, not these transitions.

   **Fix:** maintain/reselect the identity's eligible authority winner on release, trust changes, tombstone and key changes, using the same event handlers during replay. Test release → notice and competing-identity trust/tombstone sequences.

4. **P2 — The new recovery workflow depends on snapshots outside the supposedly preserved run.** `scripts/smoke_sleep.py:215`, `scripts/smoke_sleep.py:230`, `baselines/sleep.py:67`, `results/smoke_sleep/DIAGNOSIS.md:104`.

   The actual `ours` checkpoints reference `C:\Users\aadit\AppData\Local\Temp\sleep-backend-...` directories. Those directories currently exist, but they are not inside `results/smoke_sleep/` or its `run1/` archive. Preserving adapters and JSON checkpoints does not preserve these backend snapshots: `load_state()` reads the absolute external path. Temporary-directory cleanup or moving the archived run breaks `--recover` despite the archived adapter files still being present. Step4 deliberately places snapshots under its output tree, but the local smoke/recovery path does not.

   **Fix:** retain smoke snapshots under the run directory and use relocatable references, or export a complete snapshot bundle and resolve paths against that bundle. Verify recovery from a copied archive after the original snapshot location is unavailable.

5. **P2 — A successful smoke receipt does not establish the required two-T4 execution.** `step4/run.py:408`, `step4/run.py:425`, `step4/hf.py:13`, `step4/kernel-metadata.json:8`.

   `CUDA_VISIBLE_DEVICES=0` is accepted, and each worker's check for exactly one visible GPU still succeeds. The full-run receipt check verifies only arm completion, not GPU count/model or which devices actually ran workers. Metadata merely enables GPU; it does not establish a two-T4 allocation. Thus a one-GPU smoke/full run can complete successfully while violating CLAUDE.md's explicit rule. The default `0,1` works only when the surrounding allocation supplies it.

   **Fix:** validate two distinct T4 devices before expensive setup/work, persist the detected topology and actual worker assignments, and validate the matching smoke receipt's hardware. Keep any deliberate single-device development mode explicit and ineligible as a Kaggle full-run receipt.

6. **P2 — `eager` does not guarantee the promised reference DeltaNet path.** `step4/hf.py:41`, `step4/run.py:90`, `step4/hfbackend_qwen35.patch.md:74`.

   The pinned Transformers implementation selects DeltaNet's convolution, recurrent/chunk kernels and gated norm from optional installed libraries independently of the full-attention `attn_implementation` setting. Consequently a Kaggle image containing FLA/causal-conv1d can select compiled kernels despite the package's reference-path assumption. This is conditional on the environment; no actual T4 failure was observed. [Pinned Transformers implementation](https://github.com/huggingface/transformers/blob/v5.3.0/src/transformers/models/qwen3_5/modeling_qwen3_5.py).

   **Fix:** explicitly select/assert the intended reference functions, or support and record the detected optional kernel versions and capabilities. Exercise this under the exact pinned environment before the GPU run. The current optional CPU tests use Transformers 5.22.2, whereas deployment installs 5.3.0.
