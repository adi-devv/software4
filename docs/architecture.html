Software4 Architecture

A brain-inspired model that keeps learning after deployment, in its own weights. This page shows what the system looks like, why it is built this way, and how far we have got.

Milestones

6 of 11 steps done, first sleep loop built, fixing 3 failing checks

  1. Step 0

    Feasibility check

    done 2026-11-05

    Added the frozen core, a first expert and a first memory layer, on Kaggle. All 7 checks passed. fp16 is clean on T4 and the base model scores 70% on GSM8K.

    Found the two big problems: a plain expert forgets (GSM8K falls to 10%), and experts that are all on at once interfere. The memory layer forgot far less (64%).

  2. Step 0b

    Forgetting test: replay and router added

    done 2026-11-06

    Replay keeps GSM8K at 71–74%. The router keeps both skills (A 94%, B 76%), while both experts on at once drop B to 0%. Memory layer with replay: skill 82%, GSM8K 77%.

    Toy test with one seed. Replay overlaps the math test, and the router's task was easy.

  3. Step 1b

    Pilot: several sleep cycles

    GO for experts, 2026-11-07

    3 sleep cycles in a row with a simple gate, on small hand-made tasks. Experts kept all three new skills (91%, 70%, 48%) with GSM8K and ARC unchanged, and beat the best text peer (RAG, 7%) by 62 points. The memory-layer arm failed: the gate rejected sleeps 2 and 3.

    Tiny tasks, one seed, a noisy 30-item gate. The oracle peer scored 0%, probably a weak 2B model on hard rules. A green light to continue, not proof of the claim.

  4. Step 2

    Add the hippocampus

    built and retrieval-checked, 2026-11-07

    Memory graph, plastic link strengths, fast-then-deep recall, append-only log. Built separately in hippocampus/.

    Retrieval-only check, no language model: it matches or beats plain RAG in every category (plain, revised, multi-hop, near-duplicates, poison, up to 10,000 facts). A first run exposed a weakness (confident wrong hits, multi-hop skipping the deep pass); fixed and confirmed on fresh seeds. Multi-hop recall@1 is capped at 0.5 because two facts are needed.

  5. Step 3

    Evaluation harness

    built, reviewed, 138 tests pass

    Synthetic task streams, hidden tests, sealed test set, canaries, confidence intervals. Built separately in harness/. Unpaired comparisons need about 4,400 tasks per arm; the 1.7k figure holds only for paired tasks.

    Review fixes: arms receive facades with no answer-bearing references; checkpoint saves run under the arm lock; split audits block invalid streams. Sleep can score a gate once through trusted internal grading, with other arm code still locked out.

  6. Step 4

    Baselines

    built, reviewed; 385 tests pass across the repo

    Review fixes: HF chat templates and matching token counts, distillation batches bounded by input capacity, chronological evidence, and a shared Context/Task prompt format. Real-model quality remains unevaluated.

    Arms 1–4 and 10: no memory, RAG, long context, text notes, hippocampus only.

  7. Step 5

    Add the full sleep loop

    thin version in progress

    Select, replay, check, train and gate, with experts and the memory layer (arms 5 and 6).

    Thin loop built and checked on the GTX 1650 with Qwen3-0.6B (about 11 min per run): it learns a new rule into its weights, keeps it, and leaves the frozen core untouched. All 7 local checks pass after the independent review fixes (2026-11-07), including router, old-fact-vs-revision and rollback of a broken expert. An Opus plan review then changed the Kaggle run design: RAG and text notes get a fair 512-token budget (a 64-token starved RAG row is kept), new hippo_only and expert_only arms, a fresh world with 120 hidden items per rule scored per family, 3 cycles, and a stop rule written before the run (ours must beat fair RAG and hippo_only by 15+ points, 95% CI above 0). Next: CPU test, smoke, then one Kaggle run on Qwen3.5-2B; dreaming and ablations only if it passes.

Budget doesn't decide the architecture. Parts that don't fit the budget wait until they do, and they stay in the plan.

Decided against

  • BDH (Dragon Hatchling) as the core: it has no released weights and must be trained from scratch. A short-term layer inspired by it stays as experiment E10.
  • Surprise-based selection: it attracts poison, and training on unknown facts raises hallucination (2405.05904).
  • A model judging its own work: see grounded checks above.
  • A fixed 8B reflector in the loop: the model learns by itself. A bigger model only writes tasks and tests, and experiment E1 tries it for dreams.
  • Weight merging across base models: we rebuild from the log instead.
